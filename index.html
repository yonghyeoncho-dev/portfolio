01

DevPack 제품 UI 설계

역할
초기 구축 멤버 · UI 설계 (UI/CSS 층)
기간
2019.08 – 진행 중
대상
기업에 공급되는 사내 솔루션
상황
시스템관리 · 메뉴관리 · 코드관리 같은 공통 화면을 SI마다 처음부터 다시 만들고 있었습니다.
한 일
초기 구축 멤버로 PC · 태블릿 · 모바일 전 버전의 화면을 설계했습니다. 화면 유형별 템플릿 일곱 가지(Single Grid · Master Detail · Shuttle · Search Popup 등)와 정보 구성 원칙, 데이터 정렬 규칙을 가이드 54쪽으로 정했고, 테마 7종(화이트 · 블랙 · 블루 · 딥블루 · 라이트블랙 · 오렌지 · 쿼츠라이트)을 만들었습니다. 2025년부터 범정부 UI/UX 디자인 시스템(KRDS)을 반영했습니다.
결과
제가 참여한 넥사크로 외부 사업 14건이 모두 DevPack을 뼈대로 했고, 신규 프로젝트는 조립에서 시작합니다.
증거물
디자인 가이드 54쪽 · 제품 안의 컴포넌트 가이드 메뉴 · 테마 7종
02

모바일 원전건설사업관리 — 제안에서 수주까지

역할
UI 구조 제안서 작성 · 발표, 설계 총괄
기간
2025.07 – 2025.10
고객사
한전KDN
상황
모바일 화면 고도화 요청이 있었고, 화면 전체를 유동형(Fluid)으로 만들자는 안이 먼저 나와 있었습니다.
판단
유동형은 화면 수가 늘수록 설계와 유지보수 부담이 빠르게 커집니다. 국내는 쓰는 기기가 정해져 있어 그 부담을 질 이유가 없다고 보았습니다.
한 일
요청받지 않았지만 구조 제안서 20쪽을 직접 쓰고 발표했습니다. 고정형과 모듈형을 기본으로 하고, 기기가 정해지지 않은 해외 화면에만 유동형을 일부 쓰는 혼합 구조를 제안했습니다.
결과
제안이 발주처 최종 승인을 받아 실제 수주로 이어졌습니다.
증거물
UI 구조 제안서 20쪽 (2025.07) · 아래는 제안 내용을 다시 그린 것
세 가지 구조를 비교하고 섞어 쓰는 안을 냈습니다
고정형 (Fixed)구현이 빠르고 안정적. 공수를 예측하기 쉬움
모듈형 (MLM)부품 단위로 나눠 재사용. 유지보수가 쉬움
유동형 (Fluid)어떤 기기에도 대응. 화면이 많으면 공수 급증
국내 · 기기가 정해짐고정형 + 모듈형
해외 · 기기 미정혼합형, 유동형은 일부만

PRINCIPLES

검증된 표준에서 출발하고, 규칙은 문서로 남깁니다

이 사이트도 같은 기준으로 만들었습니다.

01

정부 표준을 고쳐 씁니다

범정부 UI/UX 디자인 시스템(KRDS)을 실무와 AI 도구가 바로 따를 수 있는 규칙 문서로 재구성했습니다. 회사 홈페이지와 이 사이트에 적용했습니다.

02

규칙은 문서로 관리합니다

2026년부터 프로젝트를 규칙 문서(md)로 관리하는 방식을 사내에 도입했습니다. 지금은 전 프로젝트의 기본 구성이고, 디자인 규칙 문서는 디자이너 3명이 참고합니다.

  • CLAUDE.md — 작업 원칙
  • KRDS.md — 디자인 규칙
  • DESIGN.md — 화면별 결정
03

표는 밀도와 정렬이 먼저입니다

운영자가 하루 종일 보는 화면이라 꾸밈보다 읽는 속도가 중요합니다.

  • 조회 영역은 항상 맨 위
  • 코드는 가운데, 글은 왼쪽, 숫자는 오른쪽
  • 본문 글자 크기는 하나, 위계는 굵기와 색
  • 강조색은 한 화면에 한 가지 역할만
